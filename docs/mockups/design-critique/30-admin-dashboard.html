Admin dashboard

Instance admin home (U9). The old page showed "3 Users, 0 in the last week". This one answers three questions on a LAN night: what is live, what is broken, what do I fix first. Operate mode: no hero metrics, full width, every problem has an action.

Busy LAN night New

Live parties first, with the same playback words as each party Dashboard (Playing, Paused, Nothing playing, Player stale). Problems sit next to system health, activity underneath.

  • Round 3 (all pages): page head 40/800 and card titles 650 for a clear type step; empty states use the record-sleeve icon in the colours of the cover now playing.
  • Round 3: Playback uses the shared state pill: Playing green with bars, Paused amber (was grey), Player stale red, Nothing playing grey. Needs attention count is red; all clear is a green empty state instead of a single green row.
  • The Playing bars move (1.1s, alternating) to say "live"; static under reduced motion.
  • Live parties (U9): one row per active party with name and code, playback state, what is playing, guests online, Requests waiting, Flagged waiting, owner, and a link to that party's Dashboard. A stale Player shows its fix reason under the badge, in words.
  • Needs attention (U9): every row is an instruction with its own action ("Open Dashboard", "View users", "Open Horizon", "See reviews", "Fix provider"). Red rows block playback; yellow rows degrade it. Same wording as the party Dashboard's Needs attention (#418).
  • System health (U9): workers, scheduler, Reverb, Redis, database and Spotify app credentials as plain rows with a fact in words. The dark frame shows a degraded row (Spotify rate limited). Links to Pulse and Horizon are repeated here because that is where an admin goes next.
  • Activity: sign-ups and parties created this week, Played Tracks today, a four-line recent list. Small datagrid, not hero tiles.
  • New data the app does not expose today (Admin HomeController returns only user totals): live party list with playback state, guests online, Requests waiting and Flagged waiting per party (Party, UpcomingSong, AiReview queries; guests online from Reverb presence); stale Player detection and Spotify link expiry (LinkedAccount token state); failed jobs in the last hour (Horizon failed_jobs); AI reviews that failed open (AiReview outcome low_confidence from a timeout); provider misconfiguration (SocialProvider enabled with a missing required setting); worker, scheduler, Reverb, Redis, database and Spotify credential checks; sign-ups, parties created and Played Tracks counts; the recent events list.
  • Width: full container, because the page is dense (width rule 12). Heading outline: h1 Dashboard, then h2 per card (critique-b skipped heading).

All clear and quiet instance New

The two calm states. All clear still names what was checked so silence is not mistaken for broken. A quiet instance explains what "live" means and offers the one next step.

  • All clear keeps the Needs attention card (green row, "Nothing needs attention") so the layout does not jump when something breaks.
  • No parties: empty state with "Create a party" as the only filled button on the page. Open question: the definition of live ("Player reporting or guests connected") is a proposal; it decides which parties appear.
