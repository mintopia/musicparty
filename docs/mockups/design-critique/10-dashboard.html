Schedule a Request New

Round 1’s calendar picker returns on the Upcoming list. The calendar-clock button opens a small popover (Tabler card with the app’s own buttons): a month calendar, a time field with three quick choices, a plain sentence that says when it will play, and a Schedule button. A Scheduled Request plays as soon as possible after that time (GLOSSARY.md).

  • From round 1: the calendar-clock action, the “Plays at 21:40” pill on Dancing Queen, and the scheduled state tinting the action.
  • The picker is a labelled dialog: Escape and Cancel close it, days before today are disabled, every day has a full-date accessible name, and the time is a plain 24-hour field (U5, #419).
  • The sentence under the time says what will happen (“Plays at 21:50 today, after Everybody”) before the button commits it; the button repeats the time.
  • A Request that is already scheduled opens the same picker with a Clear schedule button.
  • Round 2 used a plain clock icon with no picker; the built page uses a datetime-local field per Request (ScheduleRequestControl.vue).

  • The Start Playback badge uses the status name (Nothing playing, Outside the party, No device), matching the headline and the Needs attention item (U1, #418).
  • Outside the party: play/pause is neutral so Start on Jess’s Spotify is the single primary (A cognitive load). The skip hint stays.
  • Needs attention items are instructions with an action: “No device: Open Spotify on the DJ laptop or wake the Encore speaker” with Refresh devices (#418).
  • The empty player says what to do next instead of repeating the status word.
  • Device picker, Will play preview and Refresh devices are as built (U1).
  • From round 1: the idle player gets the icon tile beside a headline and one sentence, instead of a boxed empty state; the health facts sit in a single quiet row.

Something needs fixing Changed

Stale and expired states state the fact in words and carry the fix next to it: in the Last update cell, in Needs attention and in the panel.

  • “64800 min ago” becomes “3 minutes ago · stale” or “45 days ago · stale”, with an Open Web Player fix link under it (A-P1, #418).
  • Needs attention reads “Player stale: Encore stopped reporting 3 minutes ago” with Open Web Player (#418).
  • Re-link needed shows Re-link Spotify in the panel as the one primary, in the Spotify link cell and in Needs attention. The device picker is hidden because it cannot work without a link, as built.
  • Precedence when several are true is in the table above: Re-link needed beats No device beats Player stale.
  • The headline carries the name (“Player stale”, “Re-link needed”); the fix still sits next to the fact in the Last update cell, in Needs attention and in the panel.

Moderator view New

Moderators are a new party role. Dev sees Dashboard, Queue, Search, Requests, Moderation and Members; there is no Settings in the sidebar and no Encore relay in Quick links. The Start Playback panel says who can start playback.

  • Start Playback is replaced by a note: “Only Jess can start playback on their Spotify” (decision 6, U5).
  • Transport, rate, Upcoming schedule/remove and Flagged Request approve/reject stay available (U5).
  • Open question: may moderators pause and skip without starting playback? Mocked as yes.

Dark mode Changed

The app’s own dark mode (data-bs-theme=dark). The band and deck panels are dark in both themes; the Upcoming list, cards and page chrome switch.

  • Only Tabler tokens and deck tokens are used, no hard-coded greys; pill, health fix links and the moderator note are readable on both.
  • The headline dot, the Plays at pill and the vote capsule use Tabler tokens, so they switch with the theme.
