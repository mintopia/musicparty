Requests

The Requests table and Request detail, with combined search (#426), and the manager and moderator actions (U5, U7). Party "Coyote LAN 26", code KXQB.

Requests list Changed

The table keeps its columns and gains a combined search, filter chips, a Requested by column and a row menu. It runs full width because it is a dense table. Moderators see the same page as the owner.

  • Round 3: page head 40/800 and card titles 650 for a clear type step; empty states use the record-sleeve icon in the colours of the cover now playing.
  • One search field above the table matches every text column and understands typed filters; the chips set the same filters. The sidebar of four fields is gone. #426, U7.
  • "Sent to Player" is one column: a time in words or "Not yet". It used to read "Not Sent to Spotify" or a time. A pending schedule shows as a badge on the Request, not in this column.
  • The Requested by column is new data on this page, so moderators can see who asked for a Flagged or removed Request. Fallback Playlist Requests say so. U5.
  • Remove and Schedule moved into a labelled row menu (Open Request, Schedule Request, Remove Request) shown open on the second row. Remove says why it may not apply. Moderators have the same menu. U5.
  • Ages in words; sort carets only on the sorted column. The Votes column is the count, Score is up minus down.

Filtering and no matches Changed

Typed filters and chips are the same thing: typing sent:no artist:abba presses Waiting and adds a removable Artist chip. When nothing matches, the page says what was asked and offers the way out.

  • The count in the field says "2 of 42 Requests" so the effect of a filter is visible before the table. #426.
  • The empty state repeats the query and says which part to drop. One filled button: Clear filters. Today it says only "Try a different name, artist, album or type".
  • Filter keys in the hint line are the same words as the column names, so they can be learned from the table.

Request detail Changed

The detail page uses the same page head, cards and avatars as the list. It adds the AI review outcome with a link and a history of what happened to the Request. Schedule stays for managers and moderators.

  • h1 is the track; Schedule, Votes and History are h2 card titles, so the outline never skips a level. #425.
  • AI review outcome (Allowed, no criterion) links to the review in Moderation. The "Moderate" button is gone; Remove Request lives in the page menu (More actions). U5, U4.
  • History merges the old Votes, Other Appearances and Ratings empty cards into one list of what happened, with Played Tracks as a link.
  • Only the Save schedule button is filled; View on Spotify is outlined (it was a green filled button).

Guest view Changed

If guests are allowed to see Requests, they get the same table without the row menu and without the Flagged chip. Their own Requests carry a "You" marker.

  • Open question, not decided here: today guests do not see Requests in the sidebar (navigation.ts shows Queue and Search only) and opening it by URL returns 403. This frame shows what a guest view would look like if the answer is yes.
  • No remove or schedule control for non-managers, as on the Queue. U5.

Requests on a phone Changed

At 390px the table becomes a list: track and artist on full width, who and when beneath, send state and votes on the last line, and the row menu at the end.

  • Title and artist are never squeezed into a column beside numbers. Chips wrap beneath the field and are 44px tall on touch.
  • The row menu items are 44px with labels, so Remove is not a bare icon. U5.
