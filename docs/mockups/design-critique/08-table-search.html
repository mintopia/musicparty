Design critique mockups

Search above tables

#426 · The filter card on the left goes; a search bar and filter controls sit above a full-width table. Applied filters are listed under the bar as removable tags with a result count, so what is narrowing the list is always visible. On phone each row becomes a stacked card (no sideways scrolling). Moderation uses #417 vocabulary: nav, title and tab all say Moderation and Flagged Requests.

Admin Users

Dense table: full width, no stage band (not a party page). Nickname is the search box; ID is a small field beside it.

  • Search is a 48px field with an in-field clear button; ID filter is an inline-label field that turns blue when set.
  • Result count sits in an aria-live line under the bar; each applied filter is a tag whose whole pill removes it, plus “Clear all” once any are set.
  • Sorted column header shows a filled caret and aria-sort; the sort button is real, 44px on touch.
  • Phone: header row hides visually, each user is a card with the nickname, ID top right, then Last login and Created as labelled pairs. 16px padding all round.

Party Members

Party page: now-playing strip stays above the content. Role is a select field in the bar.

  • Same bar as Users; Nickname search plus Role select cover both filters that exist today.
  • Role cell is plain text weight 600, not a coloured badge: roles are not a status.
  • Avatar initials stand in for the real avatar; edit is an icon button with an accessible name.

Moderation: Flagged Requests

Nav label, h1 and first tab agree. Reasons are toggle chips with counts; Requested by is a select. Approve and Reject stay on the row.

  • Flagged Requests has no filters today; this adds search, reason and requester so a busy queue of held Requests can be triaged. Open question for the reviewer: keep or leave to search only?
  • The nav item carries the same count badge as the tab, so the number is visible before you arrive.
  • Reason is a warning pill plus a sentence saying why; “AI review” links to the review.
  • Phone: Approve and Reject become two full-width 44px buttons under each card.

No results

Filters that match nothing keep the bar and tags in place and replace the table with an empty state that says which filters did it and offers a way out. Also shown for Moderation.

  • The count line reads “0 of 48”, so it is clear this is a filter result, not a party with no Members.
  • Two ways out: Clear all filters (primary) and removing a single filter. Copy names the filters in plain words.
  • A true empty state (nobody has joined yet) is a different screen: no bar, one invite action. Not repeated here.

Requests (bonus)

The fourth page in #426. The four filters become one search box (title, artist or album) plus Type. “Sent to Spotify” is always a time in words or “Not sent yet”, never a yes/no.

  • Open question: Name, Artist and Album become one query. If managers need per-field search it can be a “Search in” select; not drawn.
  • Sent column: muted “Not sent yet” text instead of “Not Sent to Spotify”, so the column reads as one kind of value.
