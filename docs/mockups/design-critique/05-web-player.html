Design critique mockups

Web Player

Ticket #423. The page the host leaves running all night, now readable from across the room: album art, track, artist and a clear status, with big controls and shortcut hints. Space toggles play/pause, N skips (also on the Dashboard); shortcuts are ignored while typing in a field.

Playing

Desktop shows the Web Player inside the app shell; the TV frame is the same page at 1920×1080 with larger type and controls for a projector.

  • Same party stage as the TV page and now-playing strip: tinted by the album art, white text, one green Playing pill as the status.
  • Track is 60px on desktop and 96px on the 1080p frame; artist is 28px and 52px. Readable at about 10 metres on a projector.
  • Controls are round and large (96px Pause or Play, 72px Skip). Each carries its label and keyboard hint underneath: Space Pause, N Skip.
  • Footer line: connection state and last update in words, plus Up next so the host can confirm the Queue from across the room.
  • Pause swaps to Play (with a Paused pill) when stopped; same layout, so no jump.

Not connected

When the browser loses Spotify the page stops pretending: red signal, plain-language cause, one recovery action.

  • Headline replaces the track block; the last track is kept small at the bottom so guests and the host know what stopped.
  • Reconnect is the primary light button; Open Dashboard is the fallback. The playback controls are not shown while disconnected, rather than shown disabled.

Phone

A host may run the Web Player from a phone. Art on top, status, track, then thumb-sized controls. Keyboard hints are dropped on touch.

  • Controls stay 88px and 64px; volume goes full width beneath them.
  • The Playing pill and track title come directly under the art so status is never below the fold.
