Music Party mockups

Search

Search for guests (U3): the approved results layout, built from the real Search components, plus the empty page and the new no-close-matches notice. Band, form and results are unchanged except where each section says so.

Search, empty Changed

Today the empty Search page is a title and a box, with nothing to tap. It now offers three starting points under the same box: more like what is playing, what people at this party searched for, and the artists requested most tonight. The Search form and everything below results are unchanged.

  • "Playing now" seed: one tap runs a search seeded from the playing track ("More like Midnight City"), for guests who have no idea what to type (A-H7, persona Priya).
  • Recent searches at this party: chips, 44px tall, newest first, shared across guests so the party's taste is visible. New data: a per-party search log.
  • Most requested tonight: artists by Request count, using the app's own round artist tiles with a Requests line instead of "Artist". New data: Requests grouped by artist.
  • Section headings are h2 (they were h3 under the h1, skipping a level) at the same size (#425). The column is the centred 960px width (decision 12).

Search results overview Unchanged

The approved option A layout, built from components/Search/*: Top result beside Tracks, then swipeable rows of Albums and Artists with "See all" links. Rendered unchanged; the only edit is heading level (h3 to h2).

  • U3: layout, tile sizes, top result card and track rows are the approved design.
  • Track rows show every Add state from the approved states sheet: in the Queue with votes, Add, added by you (just now), played in the last hour. They are listed together below.
  • Votes in results use the same 44px VoteControl as the Queue.

Add button states Unchanged

The five states a result row can be in, from the approved search states: can be added, added by you, already in the Queue, played in the last hour (disabled, with the reason), and awaiting approval (Withdraw).

  • Copy is the app's own (TrackRow.vue): "Add", "Played in the last hour", "Awaiting approval", "Withdraw". "Added" is the in-Queue state with your vote already counted.

Loading, error, no results Changed

Loading, error and empty are the approved states. A nonsense query now says plainly that nothing matched closely, above whatever weak results came back.

  • Loading: every heading renders at once and each block keeps its real size, so nothing jumps when results land (approved).
  • Error: one card, Retry reloads the results and keeps the query in the box (approved).
  • No close matches (new, A-H9): when Spotify returns only weak matches the page says so in a notice above them, instead of presenting them as if they were what was asked for. A truly empty result keeps the approved "No results" card.
