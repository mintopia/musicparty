Music Party mockups

Admin settings and Mods

Instance Settings (U8). Same pattern as party Settings: tabs that share one width, SettingRow rows with a reason under every label, previews where the setting is visual, a compact table instead of wrapped URLs.

General Changed

Site, Defaults and Music providers on one tab. Each setting says what it does in a line; the change bar appears only when something is unsaved.

  • Grouped sections (U8) with h2 headings: Site, Defaults, Music providers. The old page was one 14-field column with a Themes card beside it and Social Providers underneath.
  • Default party code uses .mp-code-input and the four-letter rule in the hint (decision 4). It was "Default Party Code, NPRN" with a digit-bearing example.
  • Timezone is a picker (it was an empty text box); Fake Music Provider says local only and defaults off.
  • Sticky save bar "2 unsaved changes, Discard, Save changes" replaces the Save button at the end of a long form (same bar as party Settings).

Branding Changed

The four visual settings, each with a live preview on the surface it will appear on.

  • Previews (U8): the light-on-dark logo is previewed on the sidebar colour, the dark logo on white, the cover cropped as on a laptop, the favicon at tab size. The old fields were four bare URL boxes with no way to tell whether the URL worked.
  • Open question: keep URL fields, or add file upload (the app stores URLs today)? Mocked as URL plus preview so no backend change is implied.

Sign-in providers Changed

Six providers in a table that fits the page: status as one badge, return URLs behind copy buttons.

  • Status badge merges three Yes/No columns (Supports auth, Enabled, Auth enabled) into one word: Sign-in on, Linking only, Needs a secret, Off. The misconfigured one (Steam) says why.
  • Return URLs are two copy buttons, "Sign-in URL" and "Linking URL" (hover shows the URL). Wrapped 90-character URLs are gone. The edit page shows them in read-only fields with a Copy button and a "Copied" state.
  • Provider edit: secret is write-only ("Replace"), with the error stated in plain words under the field. Enabled and Sign-in enabled keep their meaning.
  • New data: the "Needs a secret" status is derived from enabled plus an empty required setting (also feeds Admin dashboard Needs attention).
  • The word "Sign-in" replaces "Social" in the tab name; the nav and breadcrumbs for the old "Social Providers" heading would follow. Open question: confirm the naming.

Themes tab Changed

The Themes card moves out of the Settings form into its own tab. Editing a theme opens the editor on the next page (33).

  • List shows a thumbnail built from the theme's own colours, Active as a badge, mode and last update in words. "Make active" is a button on the row; Delete is outline-danger and absent on the built-in Default.
  • New data: thumbnail colours come from the theme tokens already stored; "Updated" needs the updated_at timestamp (exists on the model).

Mods (instance) Changed

Installed mods as rows with a switch, description and a one-line state. Settings expand inline, as in the party Mods tab.

  • Row language matches the party Mods tab (#417): one switch per mod, settings only when on. The page was an accordion titled "Mod settings" with Save per panel.
  • The empty state says what mods are and what the party sees. Open question: instance on/off and per-party enablement are separate today? Mocked as "on here lets parties turn it on"; the instance defaults under AI Request Review are my assumption from ADR 0014.

Phone Changed

Setting rows stack, hints get the same side padding as labels (critique-b: hint 8px from the edge).

  • Tabs scroll horizontally inside their own row, the page does not. Save bar stays at the bottom of the viewport.
