Design critique mockups

Queue: remove a Request

Issue #421. Safe remove on the Queue page: separated control, undo toast, failure toast, load retry, permission states.

1. Default, user who can remove

Remove is a trash button on the far right, behind a divider. On phone it moves into a labelled overflow menu so it can never sit under a thumb that is voting.

  • Desktop: votes pill, 1px divider and 16px gap, then remove. The gap between the last vote arrow and remove is ~36px, far past the 8px minimum between 44px targets.
  • Remove is a neutral icon until hover/focus, when it turns red. It is never red at rest, so the list does not read as a column of warnings.
  • Phone: the vote pill stays 44px targets. Remove is behind a kebab button with a divider, and the menu names it "Remove from Queue" with a trash icon.
  • Aria-label names the track: "Remove Take On Me from the Queue".

2. Phone: overflow menu open

Opening the menu shows the labelled action. Tapping Remove removes immediately and shows the undo toast (state 3); no confirm dialog.

  • The menu opens beneath the kebab and is right-aligned to the row so it never overflows the viewport.
  • Menu items are 44px tall.

3. Removed, undo toast

Row leaves the list straight away. The toast names the track and offers Undo, which puts it back in its original position.

  • The toast stays 8 seconds, pauses on hover/focus, and is announced as a status (`role="status"`).
  • Undo restores the Request with its votes and position; if it already played or was re-added, the toast says so instead.
  • Count and duration in the page head update with the removal.

4. Remove failed, row restored

The row comes back where it was, and an error toast says what happened and offers Retry.

  • Error toast uses the alert icon colour only; the text carries the meaning.
  • The restored row simply returns; no row-level error badge so the list does not shift.

5. Queue failed to load

The list region is replaced by an empty-state card with a Retry button. Page head and stage remain.

  • Copy says what happened, that nothing is lost, and what to do. Retry is the single primary action.

6. User who cannot remove

Remove is hidden for users without the right; nothing greys out in the list. A one-line note on the page explains who can.

  • Hidden rather than disabled: a column of greyed-out buttons the user can never use adds noise. The reason is stated once, in the page note.
  • If a disabled state is wanted instead, use `.mp-iconbtn:disabled` with a tooltip and `aria-describedby` pointing at the note.
