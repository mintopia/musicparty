Queue, guest view Changed

The PartyPlayer band, the Queue heading with its search field and the row layout (art, title, artist, credit, length, votes) are the current build. The votes move onto the shared VoteControl with 44px targets, the guest's own Requests carry a "You" marker, and Fallback Playlist tracks say where they came from. Guests get no remove control.

  • "You" marker: a "You" badge beside the title, "Requested by you" instead of the nickname, and a faint row tint, so a guest finds their own Requests in a long Queue (#420).
  • Fallback Playlist credit: "From the party's Fallback Playlist" with the playlist icon replaces "Fallback Track" (decision 5).
  • Votes: the shared VoteControl replaces the old .vote-icon grid; every vote button is 44px (the 28px default is raised on every device here, not only on coarse pointers) (#420).
  • Heading level: the Queue heading is now the page h1 (it was an h3 under a sidebar h1), same size as before (#425).
  • Phone: votes drop under the text so titles keep the whole row width; length moves into the credit line.
  • Unchanged: player band, search field row, art size, text hierarchy.
  • From round 1: rows lose the card border and sit on hairlines, a position number leads each row, artist and requester share one line with the requester in bold, art is 48px with a soft corner, and the votes sit in a rounded capsule.
  • From round 2: the shared VoteControl (the capsule is only its background), the “You” badge and row tint, the Fallback Playlist credit, 44px vote buttons, guests without any remove control.

Queue, owner and managers Changed

Managers get the same rows plus a remove control, separated from the votes by a gap and a divider so a vote tap never lands on Remove. On a phone, remove moves into a labelled overflow menu.

  • Remove sits after a 1px divider and 16px of space, 44px square, danger-tinted ghost button (#421).
  • Phone: the overflow button has an accessible name ("Actions for Mr. Brightside") and the menu items carry visible labels, with a reason line under the destructive one (#421).
  • Non-managers never see either control: see the guest frames above.
  • From round 1: managers get the calendar-clock Schedule action and the trash Remove action after one divider; a Scheduled Request shows a “Plays at 21:40” pill beside its title and its calendar button is tinted. The pill is shown to managers only here; whether guests may see it is open.
  • From round 2: Remove stays separated from the votes by a divider and a gap; on a phone Schedule and Remove move into the labelled overflow menu with a reason line under the destructive one.

Schedule a Request from the Queue New

Managers can schedule straight from the Queue. The calendar-clock button opens the same picker as the Dashboard: month calendar, time field with quick choices, a sentence saying when it plays, and a Schedule button.

  • From round 1: calendar scheduling on Queue rows for managers, with the same Plays at pill afterwards.
  • Same dialog as the Dashboard (see 10-dashboard.html): Escape and Cancel close it, past days are disabled, a Scheduled Request opens it with Clear schedule.
  • Guests never see Schedule or Remove.

Remove: undo and failure New

Removing a Request is immediate and reversible. The toast names the track and offers Undo. If the server refuses, the row stays (marked), and the toast says so with Retry.

  • Undo toast: names the track, Undo button first, close second. In the app the toast stays fixed top right; it is drawn under the list here so it shows in the frame (#421).
  • Failure: the row is restored where it was with a red edge, and the toast uses the danger variant with Retry (#421).
  • Undo window length is a build decision (proposal: 8 seconds, paused while the toast has focus).
  • The undo and failed-remove toasts, the restored row with its red edge and the Retry action are unchanged from round 2; only the rows behind them use the calmer layout.

Queue failed to load, and empty New

A failed load says what happened and offers Retry. An empty Queue points at Search with a button instead of only telling guests to search.

  • Load failure reuses the Search error card pattern (cloud icon, one sentence, Retry) so errors read the same everywhere (#421).
  • Empty Queue keeps the app's EmptyState and adds "Search for a track" as the single filled button (#420).
  • The empty Queue and the load failure use the shared round-3 empty state (record-sleeve icon, 22px title); copy and the Search for a track button are unchanged.
