Music Party mockups

Party Settings

Round 2 (#417, #424, #425; U4). Built from the live Settings page (Edit.vue, PartySettingsFields, PartyModsTab) and the approved tabbed information architecture. The player band above the page is the real component, unchanged.

General and Requests Changed

The tabbed v3 Settings page as built, with the party player band unchanged above it. The page is now one centred 960px column shared by every tab, section headings are h2 under the single h1, and Country and Timezone are searchable pickers instead of a two-letter box and a datalist.

  • Section headings are `h2` (were `h3` straight under the `h1`), same small-caps look. Reason: skipped heading level (critique-b), #425.
  • Country and Timezone are pickers with search. Country shows the name and its code; Timezone adds "Use instance timezone" at the top, which is what a blank field meant. Reason: A-S settings findings, #417.
  • Labels follow decision 9: "Party is running", "Hold Flagged Requests for approval", glossary words (Request, Queue, Scheduled Request) capitalised.
  • The hint under "Hold Flagged Requests" now says where they wait (Moderation), because the Flagged page is now a Moderation tab.
  • Page width: `.mp-narrow` (decision 12). The same column holds all five tabs so the page does not jump between them. Dark frame uses the app dark mode.

Playback and Screens Changed

Fallback Playlist is chosen from the host's own Spotify playlists with cover art and track counts. Screens shows the join QR as guests will see it, with the link it opens.

  • Fallback Playlist is a picker (cover, name, track count, selected tick, search) instead of a bare select plus an "Other playlist" ID box. "Use a playlist link or ID" is kept at the bottom of the list for playlists outside the host's library. Reason: #424, decision 5 (name is Fallback Playlist everywhere).
  • "Save played tracks to" uses the same picker so both playlist fields look and behave alike.
  • Screens: when the QR is on, the row shows the code and the join link `/parties/KXQB` with Copy and "Open TV screen". The TV page itself is unchanged (U2); this only previews what it shows. Reason: #422 asks for the join URL near the TV; the QR is the URL.
  • Encore relay rows are as built; copy buttons keep their labels.
  • Playback keeps the "Show advanced" disclosure for the Context playlist. Advanced settings stay folded; device and polling are visible on the Dashboard (U1).

Mods Changed

Each mod is one row with a switch; turning it on expands its settings underneath. The settings are the real ones in code: AI Request Review (app/Mods/AiRequestReview), Trust and Whamageddon. Secrets show as saved, rarely used settings sit under Show advanced.

  • AI Request Review: "Driver" is now "Review engine" with the two engines named in words. API key shows "Saved" with Replace key (never the value). Confidence threshold takes a % suffix. Include party context, Guidelines as built. Decision endpoint, Decision model, Timeout, Endpoint and Model move under Show advanced. Reason: U4, ADR 0014.
  • Validation: the error sits under the field it belongs to, in words ("Enter a whole number from 0 to 100"), and the mod stays open. Saving with an error keeps the Mods tab selected, as built.
  • Trust: Trusted user (user picker, defaults to the owner), Maximum score bonus, Window (days), Recalculation interval (minutes). Whamageddon: Track, Score per hour, Fallback name override, CSS classes. Its private Upcoming Song ID is not shown, as built.
  • Groups are Moderation and Fun, as `groupMods` does today; descriptions come straight from each mod.
  • Mod rows are the existing `PartyModsTab` markup. The change is the content and the advanced fold, not a new component.
  • The "Flagged Requests aren't held" notice is shown on the phone frame below.

Unsaved changes Changed

The save bar sticks to the bottom of the screen whenever something has changed, naming what changed. The frame is clipped to one screen so you can see it pinned while the page scrolls under it.

  • Summary reads "N changes: sections", Discard is a quiet link and Save changes is the only filled button. Built behaviour (`Edit.vue` `save-bar`), kept as is.
  • Changes span tabs and mods: the count covers every tab, so leaving a tab never loses edits.
  • Not shown: saving state (both buttons disabled, as built).

Phone Changed

At 390px each row stacks label, hint and control. Content has a 16px gutter, so hints no longer touch the screen edge; tabs scroll sideways instead of wrapping.

  • Hints and controls sit 16px from the screen edge (`p.setting-hint` was 8px). Reason: critique-b detector finding on `/parties/*/edit` at 390.
  • The save bar wraps: summary on its own line, Discard and Save changes below, 44px+ targets.
  • The Flagged Requests notice is the built `ModPanel` alert: it appears inside AI Request Review while approval is off, with a one-click "Turn on approval".
  • The Settings tab is not in the moderator's nav and the URL is not reachable for moderators (decision 6); there is no moderator Settings screen.
