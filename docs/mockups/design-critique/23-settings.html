Mods Changed

Each mod is one designed unit: a card with an icon, name, one-line purpose, an On/Off status and a switch. Under the header a status strip shows what matters at a glance (for AI Request Review: engine, whether a key is saved, last review, reviews today). Settings sit in labelled sub-sections on a two-column grid: the section title and its plain-language help on the left, the controls on the right. Turned-off mods collapse to a single quiet row. Settings, labels and defaults are the real ones in app/Mods; Review engine is the label this sheet uses for the code's Driver.

  • Round 3: the mod card CSS now lives once in mockup.css (.mc), shared with Admin > Mods. A mod that is on gets a solid icon tile; On/Off use the shared state pill; status colours use the contrast-safe text tokens in both themes. Off mods show up to two lines of description instead of one cut-off line.
  • One pattern for party and admin. The header (icon, name, purpose, status chip, Settings toggle, switch), status strip and Off row use the same structure as the Admin Mods page (32-admin-settings). The admin page can converge on this card: its rows become the same sub-sections with the instance defaults, and "On. 4 parties use it" becomes a status-strip cell.
  • AI Request Review sub-sections: Engine & key (engine choice as two radio cards; API key shows Saved with Replace key), Decision (confidence threshold as a slider with a number box, three presets and a plain-language "what happens at N%" panel with two worked cases), Guidelines (full-width editor, 10 rows, example chips, character count, tips beside it; Include party context sits under it), Advanced (Timeout, Decision model, Decision endpoint; Endpoint and Model join it for OpenAI-compatible). Default threshold in code is 50%; Strict 30, Balanced 50 and Lenient 80 are new preset shortcuts.
  • New data, not in the app yet: Last review, Reviews today (from the AI review log), the example chips and the character counter. The code sets no length limit on Guidelines, so the counter has no cap. Trust and Whamageddon status cells are derived from their settings; "In the Queue: position 4" needs a lookup.
  • Validation: the error sits under the threshold in words, the explanation panel stops claiming an outcome, and the sticky bar names the mod. Saving keeps the Mods tab open, as built.
  • No API key: the header chip says "Needs an API key", the setup panel sits directly under the strip with the key field and Save key as the one primary action, and Decision and Guidelines are dimmed and disabled until it is saved.
  • Groups stay Moderation and Fun, as groupMods does today. Other Settings tabs are unchanged.
