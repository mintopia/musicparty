Users list Changed

Replaces the ID and Nickname sidebar form. Typing searches id, nickname and linked provider at once; role:admin, provider:discord and suspended work as typed filters and as chips.

  • Round 3 (all pages): page head 40/800 and card titles 650 for a clear type step; empty states use the record-sleeve icon in the colours of the cover now playing.
  • Round 3: Spotify link status uses the shared state pill colours.
  • Combined search (#426, U7): one field, chips below carrying the same filters, result count inside the field. The sidebar card is gone, so the table gets the full 1440 width.
  • Columns: avatar and nickname (with Admin, Suspended and Signup-not-finished badges), linked-account icons (a yellow icon means that link needs re-linking), parties, last login and created in words ("45 days ago"), never timestamps. Sort stays on ID, Last login, Created.
  • Row actions in a labelled overflow: View, Edit, Impersonate, Delete (danger, separated). They were reachable only through the user page before. Impersonate names the user so it cannot be hit by habit.
  • New data: parties count per user, linked provider per user, Spotify re-link state, and the provider:, role:, suspended filters.
  • Open question: only one role (Admin) exists on the instance today; the Role filter chip is shown for it.

User detail Changed

The same facts as today, plus where the user plays and which of their Spotify or Discord links work. This is the page an admin lands on when someone says "it will not let me log in".

  • Account facts stay in the datagrid; the actions move to the page head: Edit is the one filled button, Impersonate Mina is outline and names the target. Delete moves to the account card footer, away from Edit.
  • Linked accounts (U8) as a table with provider icon, account, linked date and state. Mina's Spotify shows "Needs re-link" with the same yellow state used on the Admin dashboard.
  • Parties: each party the user belongs to with their role and last activity. New data: party memberships on the admin user page.
  • Heading outline: h1 name, h2 per card. The old page jumped h1 to h2 for Linked Accounts outside a card.

Edit and delete Changed

Edit uses the Settings row pattern (label and one-line reason left, control right). Delete keeps the typed confirmation but says what goes with the user.

  • Edit: SettingRow layout with a hint under each label (the switches had none). One filled button, Cancel as a link.
  • Delete: names the user in the title and button, lists what is removed and blocks on ownership of a party. Copy to confirm with backend: what deletion removes and the owner-first rule are proposed, not read from code.
