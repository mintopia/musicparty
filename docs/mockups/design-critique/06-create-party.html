Design critique mockups

Create Party in three steps

Ticket #424, with labels from #417. Name and code, then Music, then Guests and rules, ending on a confirmation that hands the host the code, QR and next actions. The stage band carries a live summary of the party so the form feels like building the thing guests will see.

Step 1: Name your party

Only Name is required. Country is pre-filled from the instance default and Timezone falls back to the server.

  • Stage summary shows "Name your party" until a name is typed, then the name in display type, then choices as chips as each step completes. Pending steps are dashed.
  • No party code field: codes are generated. The stage says guests join with a code shown on the TV once the party exists.
  • Rows use the same label, hint and control layout as Settings (label left, control right). Labels match Settings exactly.
  • "Create with defaults" skips straight to creation, since only Name is required. Cancel goes back Home.

Step 2: Choose the music

Spotify account and Fallback Playlist. The raw Spotify Playlist ID box and "Other Playlist" option are gone; the host picks from their own playlists.

  • Fallback Playlist is a radio list with cover art, track count and a search field, so a host with 200 playlists can find one. Selected row gets a primary edge and a "Selected" pill.
  • "No Fallback Playlist" is an explicit choice so Playlist is not required. Open question for the reviewer: today the field is required.
  • Playback Device and History Playlist sit under "More music options" (folded). They are also in Settings.
  • On phone, pills and track counts drop out to keep names readable; the 20px radio stays with a full-row 68px tap target.

Step 3: Guests and rules

The six switches and five limits from today's form, with Settings' labels. Everything is pre-set to a default; limits are folded open.

  • One label for the running setting: "Party is running" (the Settings label), with the hint "Turn off to pause the Queue. Requests wait until it’s back on." Replaces "Process the queue and requests". Default on.
  • "Show QR code on the TV" is on by default (#422).
  • Switches show their state in words (On/Off) as well as position. Only the last step says "Create party".
  • Poll the Spotify API and Force playback are not asked here; a footnote says they live in Settings.

Validation on the step that holds the field

Submitting a bad Name or Country sends the host back to step 1, with the row tinted and a message next to the field.

  • Errors say what to do, not just what is wrong. Each has an alert icon so colour is not the only cue; the row also gets an edge bar.
  • On phone the step header collapses to the current step's label plus numbered dots for the others, so three labels never wrap.

Finish: Party created

The code is the hero. Link, QR and the three jobs the host does next.

  • Same stage band and code type as the TV page, so what the host sees now is what guests will see on the big screen.
  • Next actions use the glossary words: TV page, Web Player, Dashboard. Primary button is the one needed first.
