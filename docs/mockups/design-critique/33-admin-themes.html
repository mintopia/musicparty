Admin themes

Theme editor (U8). The old form was one narrow column where every unset colour showed black and Dark Mode sat at the bottom. The editor now has the form on the left and a live preview of the app on the right, so a colour is judged where it lands.

Themes list Changed

Lives under Settings, in the Themes tab. Thumbnails come from each theme's own colours.

  • Active is a badge with the same green dot as other states; "Make active" is a row action instead of a form toggle you have to open the editor for.
  • Open question: the built-in Default is shown as a row you can activate (switching back to it). Today it is Edit and a disabled Delete.

Create theme Changed

Starts empty: every colour reads "Default" with a dashed swatch showing the colour it falls back to. Nothing is black.

  • Unset colours (U8): the swatch shows the default colour dashed and labelled "Default"; the field shows the default as a placeholder. Setting a value shows the swatch solid and replaces the label with Reset.
  • Order (U8): Name, Dark mode, Active at the top in the Settings row pattern; colours in a two-up grid; Custom CSS last and full width, because it is the advanced option.
  • Required stars on Primary and Navigation background are dropped: with defaults shown they can never be empty. Open question: confirm the backend accepts them unset.
  • Save is the one filled button, in the page head, so it is visible next to the preview without scrolling a long form.

Edit a dark theme Changed

The StratLAN theme from the approved mockup, rebuilt in the editor. The preview switches to Dark because the theme is always dark.

  • Live preview (U8): a small app shell (sidebar, a card with two rows, a badge, three buttons, a link) painted from the unsaved values, with a Light / Dark switch. It sticks while the form scrolls.
  • Preview is a mock of the app, not the real app, so it covers the tokens (primary, nav, surface, text, muted, border, success, danger, warning). Rules in Custom CSS are not previewed. Open question: render the real app in an iframe instead? More faithful, much more work.
  • Custom CSS shows the existing code editor; the note about :root applying to light and dark comes from ADR 0013.

Invalid colour and delete Changed

Validation says what was wrong and what to type; delete names the theme and says what happens to the site.

  • Invalid: the field turns red with "That is not a colour. Use #RGB or #RRGGBB, for example #d63939." The card header counts the problems. The preview keeps the default until the value is valid.
  • Delete: names StratLAN in the title and button, shows its thumbnail and says it is active and the site returns to Default. No typed confirmation: the theme is recoverable only by re-creating it, so this is lighter than deleting a user (open question).

Phone Changed

Editing a theme on a phone is a stretch, but a quick fix at a venue should work: the preview moves below the form and stays static.

  • Colour fields are one per row; the preview follows the form (not sticky). Save stays in the page head at full width.
